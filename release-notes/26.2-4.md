## New: plugin API for shared data

In a Storia Cluster every worker runs its own copy of each plugin. Plugins can now share their own data and
messages across all workers with `dev.storia.api.StoriaShared` (download `storia-api-26.2-4.jar` and add it as a
compileOnly dependency):

- **A key-value store per plugin**, kept by Storia Relay: `get`, `set`, `delete`, `keys`, atomic
  `compareAndSet` (only one worker can win, e.g. for locks) and `increment` (counters, balances), and `listen` for
  changes made on any worker.
- **Messages**: `publish` / `subscribe` reach the same plugin on every worker, including the sender, in the order
  the relay received them.
- Asynchronous and non-blocking (`CompletableFuture`); listeners run off the region threads.
- **The same API works on a single server**: data is kept in `storia-shared/` and messages stay on that server, so
  plugins need only one code path.

Tested with two workers: 200 increments from each worker at the same moment give exactly 400, only one worker wins
a lock, messages and change notifications reach both workers, and the data survives a relay restart.

Guide: https://storiamc.com/en-us/docs/plugin-api/

## Also in this release

- Two workers started with the same `cluster.node-name` no longer knock each other off the cluster: the second one
  is refused with a message asking for a unique name.
